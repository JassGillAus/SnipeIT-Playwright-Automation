## Overview

This project automates the creation and validation of a hardware asset in the public **Snipe-IT** demo environment. It was developed as a technical interview assignment, with an emphasis on readable tests, reusable page objects and meaningful assertions.

## Automated Scenario

1. Log in to the Snipe-IT demo application.
2. Navigate through the dashboard to **Create Asset**.
3. Select the **MacBook Pro 13\"** model and **Ready to Deploy** status.
4. Select an eligible user at random for checkout (and a company, where applicable).
5. Capture the **Asset Tag generated by Snipe-IT** and save the asset.
6. Find the newly created asset in the assets list.
7. Open its detail page and validate the saved information.
8. Verify the relevant **History** entries.

## Project Design

The automation uses the **Page Object Model (POM)**. Each Page Object encapsulates selectors and actions for its area of the application; the NUnit test orchestrates the workflow and evaluates the results.

The key responsibilities are:

- **Login page:** Authentication
- **Dashboard page:** Navigation to asset creation
- **Create Asset page:** Form interactions and capture of selected/generated values
- **Assets list page:** Asset lookup
- **Asset details page:** Detail and history inspection
- **Test data model:** Holds values captured during the test for subsequent verification

## Quick Start

### 1. Clone the repository

```powershell
git clone https://github.com/JassGillAus/SnipeIT-Playwright-Automation.git
cd SnipeIT-Playwright-Automation
```

> Run the commands below from the directory containing the `.csproj` file. If the project is in a subfolder, navigate into it first.

### 2. Restore and build

```powershell
dotnet restore
dotnet build
```

### 3. Install Playwright Chromium

```powershell
pwsh bin/Debug/net10.0/playwright.ps1 install chromium
```

### 4. Execute tests

```powershell
dotnet test --settings test.runsettings
```

### Run with a visible browser (optional)

In PowerShell:

```powershell
$env:HEADED = "1"
dotnet test --settings test.runsettings
Remove-Item Env:HEADED
```

## Configuration

The `test.runsettings` file contains the application's **BaseURL** as an NUnit test parameter, along with test execution settings.

The test class reads that parameter using `TestContext.Parameters.Get("BaseURL")` and passes it into Playwright's `ContextOptions()`. Page Objects can therefore navigate with relative paths such as `/login`.

The configured target is the public demo at `https://demo.snipeitapp.com`.

## Validation Strategy

The end-to-end test verifies that the asset is created and can be found again. It compares details against values captured during form submission, including the generated asset tag, selected model, status and assigned user, and checks relevant history entries.

- **Playwright `Expect`** assertions are used for auto-retrying browser/UI checks.
- **NUnit `Assert`** is used for checks on captured C# values where appropriate.

## Results and Troubleshooting

Test results are written to **TRX** format via the project's test configuration. Playwright tracing is started before the test and saved on failure.

Depending on the test runner's working directory, a failure trace is written to a `TestResults` folder. Locate `trace.zip`, then open it with:

```powershell
pwsh bin/Debug/net10.0/playwright.ps1 show-trace "PATH_TO_TRACE.zip"
```

`TestResults/`, `bin/` and `obj/` contain generated files and should not be committed to Git.

## Notes

- Snipe-IT is a **shared public demo**: its data can be reset or modified by other users.
- Dropdown selections depend on the users and companies available during execution.
- The test may create a persistent asset until the demo environment is reset.
- Demo credentials are provided by the demo application; no private credentials should be committed to this repository.
